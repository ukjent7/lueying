# macOS 与 Liquid Glass 设计笔记

记录日期:2026-10-25。用途:未来 macOS 版掠影的视觉与动效方向;Windows 版不强行套用。

## 是什么

- Liquid Glass 是 Apple 在 WWDC 2025 发布的设计语言(macOS 26 Tahoe 起),取代以扁平化为主的方向。
- 材质同时表现折射、反射、透镜、磨砂与高光;玻璃随背景明暗和设备运动变化,并在不同形状间流动变形。
- 控件从贴边工具栏变成按上下文出现、收起的浮动气泡;强调内容与控件的层级;图标改为分层、透明、带高光的玻璃。
- 2026 年 WWDC 对 macOS 27 / iOS 27 做了回调:默认透明度降低、玻璃更磨砂、顶部高光更克制、边缘压暗、图标更易辨识,并加入「清晰 ↔ 着色/磨砂」全局滑杆。背景是可读性与注意力分散的批评。

## 动效哲学(可借鉴)

- 材质连续:控件展开、收起、切换时保持同一块「玻璃」的连续形变,不做硬切。
- 响应输入:高光与形变跟随指针、滚动和运动,幅度克制。
- 空间层级:用折射、模糊、阴影表达悬浮高度;同一层级共享圆角与同心几何。
- 内容优先:玻璃只承载控件,文字与候选始终落在高对比、稳定的底上。

## 性能与可用性边界(必须)

- 输入法第一指标是按键到候选的延迟和常驻内存;不低于当前 Windows 的 p95/p99 预算。
- 只在候选窗、设置窗等小面积控件上用玻璃;不对整屏背景做实时高斯模糊或折射。
- 提供「降低透明度 / 降低动态效果」开关并跟随系统辅助功能;低端机自动退化为不透明材质。
- 文字对比度优先于折射效果;候选字默认不叠在复杂透明背景上。
- 动画以 150–250ms 的形变、淡入为主,避免每帧重绘大区域;空闲时停止动画与刷新。

## 对架构的提示

- 视觉令牌(圆角、材质、阴影、动效曲线)与平台输入层解耦,Windows 与 macOS 共用一套设计令牌。
- macOS 输入法宿主是 InputMethodKit,与 TSF 不同;UI 可复用 GPUI,输入协议可沿用行 JSON 思路。
- Windows 版保持现有风格,只借鉴层级、连续形变与克制动效。

## 候选框动效评估(2026-10-25)

结论:值得做「从光标展开」和「对称收回」,按灵动岛的**原则**做,不照搬它的持续形变。

- 灵动岛成立的前提是固定原点、常驻、低频状态变化;候选框的原点跟着光标、只在组句时出现、每键都更新,逐键做整窗形变会变成视觉噪声并拖慢输入。
- 首次出现:从光标处约 140–180ms 展开,宽高与圆角连续插值,文字在 40–60ms 后淡入;首帧就画出最终布局,动画只做遮罩/位移/透明度,不能等动画结束才显示候选。
- 组句中:不做整窗形变;候选行数变化只动画高度(约 120ms),顶边锚定;选中高亮约 80ms。
- 翻页:沿翻页方向水平滑动约 120ms;进入与退出走同一条路径(**Symmetric Paths**)。
- 收回:沿展开路径反向收回约 100–140ms;上屏时 80ms 内结束或直接消失,避免残影压在正文上。
- 空间一致性(**Spatial Consistency**):固定以光标为原点、固定间距,向右下生长;下方空间不足时先决定上翻,再从上翻位置展开;翻页与换行不改变已有多行候选的几何位置。
- 工程约束:顶层窗口一次定到最终尺寸,在窗口内做内容动画;不要每帧改 Windows 窗口 bounds。动画必须可被下一次按键立即打断并跳到终态;降低动态效果时退化为 100ms 淡入。
- 验收:首候选可见不晚于按键后一帧;动画不进入输入热路径;p95/p99 延迟不退化;空闲时零动画。
