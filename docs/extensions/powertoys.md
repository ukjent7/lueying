# PowerToys 命令面板桥接

掠影扩展命令可以从 PowerToys 命令面板(Win+Alt+Space)与任何其他启动器
触发。桥接面是 CLI 一条命令:

```
lueying ext run <命令 id>
```

它把命令投给常驻服务,与动作候选、热键走同一条执行路径(`Runtime::invoke`)。
执行是异步的:快命令当次结算,等待截图、OCR 等服务的由扩展循环节拍收尾,
结果落在掠影自己的通知与日志里,启动器只负责触发。

## 接入命令面板

命令面板的「书签」支持 shell 命令,正好包住这条 CLI:

1. `lueying ext commands` 列出可用命令与完整 id(标题表,只含已加载的命令)。
2. 命令面板设置 → 书签 → 新建 shell 命令,例如命令行
   `lueying.exe ext run shot-ocr.run`,名字写「截图 OCR」。
3. 想要一条通用的触发入口,就建一条 `lueying.exe ext run {query}`,
   运行时命令面板会内联询问要跑哪条命令。
4. 书签可以固定到主页或 Dock;右键命令还有「复制命令链接」可以分享。

书签随命令面板的设置走,掠影不写系统级注册项,卸载掠影后书签只是报
「服务未运行」。

## 语义与门禁

- 只能触发脚本线程声明过的命令(标题表);未加载或已卸载的命令报
  「命令不存在」。
- 活动会话在密码/隐私字段时拒绝,与热键、动作候选同一道门。
- 每次执行走扩展的既有预算与审计;命令结果不回传启动器,管道请求在
  投递后立即返回。

## 为什么不做原生扩展

命令面板的原生扩展模型是 .NET WinRT 组件加 `.appxmanifest` 注册的进程外
COM 服务器(`com.microsoft.commandpalette` appExtension),官方工具链是
C# 模板加 MSIX 打包。对掠影来说要为此背一个 C# 工程与打包链,换来的
只有「在面板里原生列出命令」这一层外观。书签桥接零依赖、零常驻、
零新信任面;等用户量证明值得时,再按同一套命令 id 做原生 provider。
