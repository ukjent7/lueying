# 扩展分层模型

扩展按信任边界分四层。核心始终持有文本与候选的最终决定权；每层有独立的清单组件、权限和预算，坏扩展只影响自己。

| 层 | 形态 | 能做什么 | 运行位置 | 状态 |
|---|---|---|---|---|
| 声明式 | 主题、键位、短语、简单方案表 | 改配置与映射，不执行代码 | 宿主解释 | 已有零散文件，待统一包格式 |
| 逻辑 | WASM 模块 | 候选过滤/重排、输入方案、按键映射 | 宿主内沙箱 | 计划 |
| 外观 | JS 场景补丁 | 候选窗主题色与三个 SkSL 槽位 | 宿主内 QuickJS | 已实现 |
| 能力 | 独立进程 | 截图编辑、OCR、翻译浮窗等重交互 | 进程外 | 计划 |

## 原则

- 热路径上的扩展有硬预算；超时、崩溃或连续失败只停用该扩展，不拖慢击键到候选。
- 密码/隐私字段整个扩展层停用；能力扩展也收不到屏幕内容。
- 能力默认关闭，清单里逐项声明，安装时展示，运行时可撤销。
- 扩展只能按授权读写结构化数据；候选文字默认不进扩展。
- 外观层保持第一帧素色、高对比度覆盖、减少动态效果；逻辑层的结果必须经过宿主校验。
- 官方性能关键扩展继续用编译期 Rust，第三方逻辑优先 WASM，重 UI 与系统能力走进程外。

## 清单

一个包可以同时带多个组件。每个组件声明自己的 API 版本与权限：

```json
{
  "id": "my-pack",
  "name": "我的扩展",
  "version": "1.0.0",
  "appearance": { "api": 1, "main": "index.js" },
  "logic": {
    "api": 1,
    "module": "logic.wasm",
    "permissions": ["candidate-text"]
  },
  "panel": {
    "api": 1,
    "command": "panel.exe",
    "permissions": ["screen-capture", "ocr"]
  }
}
```

兼容旧的外观包：顶层 `{ "api": 1, "main": "index.js" }` 视为只有 `appearance` 组件。顶层 `capabilities` 是旧字段，必须为空。

权限按组件授权，当前集合：

| 权限 | 组件 | 含义 |
|---|---|---|
| `candidate-text` | logic | 读取候选文字，用于过滤与重排 |
| `screen-capture` | panel | 截取屏幕区域 |
| `ocr` | panel | 对截取内容做文字识别 |
| `network` | panel | 访问网络 |
| `clipboard` | panel | 读写剪贴板 |

外观组件不授予任何权限：它只收到面板状态，看不到候选文字与宿主名。

## 逻辑层（WASM）

- 宿主用纯 Rust 解释器运行，模块大小、线性内存、单次调用燃料与时间都有上限。
- ABI 版本化；输入输出走线性内存里的结构化缓冲，不直接暴露引擎内部结构。
- 候选模块拿到 `{context, candidates}`，只能回排序、过滤或分数修正；没有 `commit-text` 权限时不能改上屏文本。
- 初始化失败、连续三次派发失败或超时即停用；文件内容哈希变化时热重载，保留上一版可用的模块。
- 重活不在按键路径上做；需要网络或大模型的扩展走能力层。

## 能力层（进程外）

- 扩展是一个独立可执行文件，宿主按需启动，经命名管道通信；不把未签名 DLL 加载进输入法进程。
- 宿主提供版本化消息：`hello`、`panel.show`、`panel.hide`、`panel.anchor`、`panel.theme`、`panel.private`。
- 扩展自己创建窗口并选择 UI 栈（GPUI、egui、原生 Win32 等）；宿主只给锚点、DPI、主题与隐私信号。
- 简单结果（一段翻译、几个动作）可以由宿主用声明式面板渲染；复杂编辑交给扩展自己的窗口。
- 进程崩溃、挂起或内存超限时由宿主终止并停用；隐私字段出现时立即隐藏面板并停止派发。

## 落地顺序

1. 共享清单与权限模型：外观、逻辑、能力组件共用一份 `manifest.json`，旧外观包保持兼容。
2. 逻辑层：WASM 宿主、ABI、预算、热重载与 E2E。
3. 能力层：进程协议、权限提示、面板生命周期与一个示例扩展。
4. 声明式层：主题/键位/简单方案表统一成包格式，复用同一份清单。
