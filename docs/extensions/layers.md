# 分层、权限与运行

## 运行位置

- **内建功能**：随 `lueying-server.exe` 编译，全局默认开启，没有独立的运行边界。
- **扩展宿主**：`lueying-ext-host.exe` 是独立进程，运行全部扩展（Wasm 与原生），允许联网。服务端只经标准输入输出与它交换行协议，不加载任何扩展，也不联网。宿主崩溃或卡死时，输入法照常打字，超时的补丁一律丢弃。
- **Wasm 扩展**：以 WebAssembly 组件在 wasmtime 中运行，每个扩展一个工作线程。宿主把全部服务接口链接进组件，清单 `needs` 与权限安装时同意，同意之后服务调用按清单放行（联网例外，逐请求核对白名单）。
- **原生扩展**：宿主按需启动的独立进程，不套沙箱，也不设资源限额；扩展的风险由用户承担。

## 权限与同意

- 清单中的 `capabilities` 是扩展申请的权限，`needs` 是它要用的服务。
- 首次启用时，在「设置 → 扩展」中查看并同意。同意记录保存在 `%APPDATA%\lueying\extensions\consent.json`，内容变化后需要重新同意。
- 私密字段（如密码框）中，候选文字不交给任何扩展。私密场景只送给不联网的扩展；联网扩展只有在用户单独允许私密使用（按内容指纹记录，内容变了失效）之后才收到。

## 资源与故障

宿主不设资源预算：燃料、内存、运行时间与原生进程的内存和 CPU 都不计限额，扩展跑多久、占多少内存由扩展自己决定；连续失败也不会被停用，失败原因记在扩展指标里。Wasm 模块文件默认 ≤ 16 MiB，清单声明 `"engine": true` 的内嵌语言引擎组件 ≤ 64 MiB。

命令包空闲 30 秒后释放工作线程与实例；外观包常驻。

## 订阅候选窗状态

原生扩展可以在清单中声明 `"events": ["candidate-state"]`，宿主把候选窗的状态推给它。典型用途是贴着候选窗显示的伴随界面，例如桌宠。扩展自己开窗口绘制，宿主不共享绘制资源。

- 只对已同意的扩展生效。宿主在启动时确定订阅者，安装或同意之后需要重启扩展宿主。
- 每次候选窗状态变化，宿主调用一次 `candidate.state`，参数为 JSON：`visible`（是否显示）、`composing`（是否有组合内容）、`rect`（`[x, y, 宽, 高]`，屏幕物理像素）、`private`、`raw`、`page`、`page_size`、`highlight`、`candidates`。
- 只保留最新一条。扩展处理慢时中间状态会被跳过，不会堆积。订阅后进程常驻，不因空闲退出。
- 候选文字与组合拼音需要 `candidate-text` 权限。没有这项权限，或处于私密字段时，这两项为空，只剩位置与可见性。
- 扩展只读。它不能借此回调宿主，返回值被忽略。
