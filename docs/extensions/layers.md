# 扩展分层模型

扩展按运行位置与成本分四层,另有一类原生内置实现。核心不认识任何具体功能,只提供平台原语;每层有独立的清单、权限与预算,坏扩展只影响自己。

| 层 | 形态 | 例子 | 运行位置 | 状态 |
|---|---|---|---|---|
| 数据 | 文本或表文件 | 短语、效果文件、双拼布局表 | 宿主解释 | 已有,待统一包格式 |
| 脚本 | QuickJS,命令式 | 截图 OCR、剪贴板历史、取色、换算 | 常驻进程内的共享工作线程 | 已实现外观、命令宿主与官方 shot-ocr |
| Wasm | Wasmtime + WASI 0.3, WIT 接口 | 候选重排、输入方案 | 宿主内沙箱 | 原型 |
| 旁路进程 | 任意语言,按需启动 | 本地大模型、高精度 OCR | 独立进程,Job Object 限额 | 计划 |
| 原生内置 | 同一契约的 Rust 实现 | 双拼等每键都跑的热路径 | 编译进宿主 | 已有,逐步迁到同一契约 |

## 原则

- 扩展空闲成本为零:没有激活事件就不加载,不占线程、不占内存。
- 按键热路径不受影响:热路径钩子只给声明了触发词的扩展,预算 1–2 ms;脚本步进预算约 8 ms,等待原生服务不计时。
- 核心只提供平台原语:`capture`、`ocr`、`clipboard`、`panel`、`output.deliver`、`hotkey`、`net`、`store`、`notify`。具体功能由扩展组合这些原语。
- 一个契约:事件进、补丁出。内置功能与外部扩展实现同一份可序列化协议;补丁由宿主校验、限量、标注来源,卸载后可复原。
- 密码/隐私字段整个扩展层停用;捕获、钩子、上屏一律拒绝。
- 能力默认关闭,清单里逐项声明;安装时用人话展示,更新新增能力要重新同意。
- 外观第一帧素色、高对比度覆盖、减少动态效果;扩展不能绕过这些宿主不变量。

## 清单

API 2 的脚本清单直接描述入口与激活方式。命令只声明,不拥有按键;绑定表由用户维护,清单里的 `hotkeys` 只是建议。

```json
{
  "id": "shot-ocr",
  "name": "截图 OCR",
  "version": "0.1.0",
  "api": 2,
  "main": "index.js",
  "activate": {
    "triggers": ["ocr"],
    "hotkeys": ["Ctrl+Alt+O"],
    "commands": [
      { "id": "run", "title": "截图并识别文字", "when": "any" }
    ]
  },
  "needs": ["capture", "ocr", "output", "notify"],
  "capabilities": ["screen-capture", "ocr"]
}
```

| 字段 | 说明 |
|---|---|
| `api` | 清单 API;`2` 是脚本层清单,`1` 是旧版外观包 |
| `main` | 脚本入口,包内裸文件名,默认 `index.js` |
| `activate.triggers` | 输入内触发词,整串完全匹配才出现动作候选 |
| `activate.hotkeys` | 建议热键;宿主做冲突检测,实际绑定在用户表里 |
| `activate.commands` | 命令声明;`id` 在扩展内唯一,完整 id 是 `<扩展 id>.<命令 id>` |
| `needs` | 需要的宿主服务,没声明就调用失败 |
| `capabilities` | 申请的权限;API 1 必须为空 |

旧版外观包继续可用:顶层 `{ "api": 1, "main": "index.js" }`,或 `appearance`/`logic`/`panel` 组件式清单。API 2 不能和组件混用。

权限当前集合:

| 权限 | 含义 |
|---|---|
| `candidate-text` | 读取候选文字,用于过滤与重排;含左邻上下文,高敏感 |
| `screen-capture` | 截取屏幕区域;高敏感 |
| `ocr` | 对截取内容做文字识别 |
| `network` | 访问网络(域名白名单);外发 |
| `clipboard` | 读写剪贴板;读与写分开授权,高敏感 |

## 授权与审计

- 声明了 `needs` 或 `capabilities` 的包首次启用前要在设置页同意;纯外观
  包不需要。
- 同意记录在 `%APPDATA%\lueying\extensions\consent.json`,按扩展 id 存包
  内容哈希(清单 + 入口脚本)、版本、能力与服务。运行期只读这两个文件,
  其它数据文件不参与指纹。
- 哈希或能力集合变化即失效:新内容不热加载,旧版本先继续跑;重新同意
  后由宿主重建运行期。记录损坏按空记录处理,失败方向是停用。
- 「读取用户内容 + 外发」组合单独强提示;能力按高敏感/外发分级展示。
- 隐私字段下扩展层整个停用:热键、命令与全部服务调用被拒绝,挂起的
  `hotkey.press` 收到错误。
- 每次服务调用写 `%LOCALAPPDATA%\lueying\logs\ext-audit.log`,只记时间、
  扩展 id、服务/方法与结果,不记参数内容;设置页可打开。


## 脚本层

- 多个扩展按配置里的 `extensions=a,b,c` 顺序组合;顺序即补丁合并顺序。
- 外观包常驻;命令包按激活事件懒加载,空闲 30 秒卸载 JS 宿主。
- 触发词匹配放在 Rust 侧的前缀树,不命中就不进 JS。
- 每个扩展一个 QuickJS 运行时:内存 8 MiB、栈 256 KiB、初始化 100 ms、单次派发 8 ms。超时由中断处理器打断;作业步超出预算计一次失败,连续 3 次失败停用。
- 每次派发与作业步都记录最慢耗时;服务端每秒把状态、内存、峰值、超限与失败原因写进 `%LOCALAPPDATA%\lueying\logs\ext-metrics.json`,`lueying ext top` 与设置页「扩展运行」读同一份快照。待同意与坏包也列出,列表里能看到它们为什么没跑起来。
- 注册物(命令、触发词、热键、面板、定时器)挂在宿主 Scope 上;卸载或热重载时整体回收。
- 脚本只能执行清单里声明过的命令;JS 里注册了未声明的名字也调不到。

## Wasm 层

- Wasmtime + WASI 0.3,WIT 定义接口;扩展看到的服务与脚本层一致。
- 候选模块只能回排序、过滤或分数修正;输入输出走线性内存里的结构化缓冲。
- 版本化 ABI、燃料/时间/内存上限、连续失败停用、内容哈希热重载。
- 先做原型与体积/内存/冷启动测量,再决定是否作为默认第三方形态。

## 旁路进程层

- 扩展是独立可执行文件,宿主按需启动,经命名管道通信;不把未签名 DLL 加载进输入法进程。
- Job Object 限内存与 CPU;崩溃、挂起或超限由宿主终止并停用。
- 默认不常驻;本地大模型、高精度 OCR 这类重活走这层,不进按键路径。
- 隐私字段出现时立即停止派发并隐藏面板。

## 落地顺序

1. 共享清单与脚本命令宿主:API 2 清单、多扩展有序加载、Scope、懒加载与空闲卸载。
2. 异步步进:Promise、作业队列、每步预算与共享工作线程。
3. 服务缝 v1:capture、ocr、output.deliver、panel、hotkey、notify,先跑 Windows 实测。
4. 入口与动作候选:命令面板、绑定表、全局热键、输入内触发歧义规则。
5. 官方 shot-ocr 扩展与开发回路。
6. Wasm 与旁路进程原型,按测量结果决定默认形态。
