# 扩展分层与权限模型

掠影采用层次化的扩展架构模型。核心引擎不固化具体业务，仅对外暴露安全、可审计的平台原语；不同形态的扩展按照信任边界在专属层级中隔离运行。

## 分层架构矩阵

| 层级 | 运行载体 | 典型应用 | 执行位置 | 隔离与调度机制 |
|---|---|---|---|---|
| **原生内置** | 编译期 Rust | 双拼方案、五笔辅助码、自定义短语 | 常驻服务主线程 | 极高执行效率，按键热路径微秒级响应 |
| **Wasm 扩展层** | wasmtime JIT 沙箱 | 截图 OCR、外观着色、命令宿主 | 每扩展独立 worker 线程 | 燃料计量中断、16 MiB 内存限额、连续故障熔断 |
| **旁路进程** | 独立外部进程 | 本地大型神经模型、复杂计算 | 独立 Windows 进程 | Job Object 限制，命名管道异步 IPC 通信 |
| **数据层** | 纯文本与映射表 | `phrases.txt`、`punct.txt`、`skin.toml` | 宿主安全解析 | 纯声明式解析，无代码执行风险 |

## 架构原则与信任边界

1. **零空闲成本**：未被激活的扩展不分配独立线程与运行时内存。
2. **热路径零阻塞**：常规打字热路径仅执行声明了触发词的匹配树，匹配时间严格控制在 1ms 内；等待外部异步服务期间不计入脚本步进预算。
3. **平台安全原语**：核心仅提供受控的原语服务：`capture`（截屏）、`ocr`（离线识别）、`clipboard`（剪贴板）、`panel`（弹窗面板）、`output`（文字注入）、`hotkey`（全局热键）、`store`（私有存储）、`notify`（系统通知）、`network`（联网，经独立 broker 进程，只能访问清单白名单里的域名）、`context`（读当前窗口选中文字，需 `selected-text` 权限）。
4. **隐私场景强制挂起**：在系统密码框、私密字段及安全桌面下，扩展层整体自动熔断停用，所有外联、热键与内容提取均被系统拒绝。

## 清单规范（API 3）

扩展必须在包根目录下提供 `manifest.json`：

```json
{
  "id": "shot-ocr",
  "name": "截图 OCR",
  "version": "0.1.0",
  "api": 3,
  "wasm": "extension.wasm",
  "activate": {
    "triggers": ["ocr"],
    "hotkeys": ["Ctrl+Alt+O"],
    "commands": [
      { "id": "run", "title": "截图并识别文字", "when": "any" }
    ]
  },
  "needs": ["capture", "ocr", "output", "notify"],
  "capabilities": ["screen-capture", "ocr"]
}
```

### 字段说明

- `api`：清单版本号，当前为 `3`;`wasm` 指向包内的 Wasm 模块。
- `activate.triggers`：输入串完全匹配的触发词，用于调出动作候选。
- `activate.hotkeys`：建议的快捷键绑定（实际绑定关系受用户 `config.toml` 控制）。
- `activate.commands`：命令声明，完整全局标识为 `<扩展 id>.<命令 id>`。
- `needs`：声明需要使用的宿主服务原语。
- `capabilities`：向用户申请的权限集合。

### 权限模型体系

| 权限标识 | 权限说明 | 敏感级别 |
|---|---|---|
| `screen-capture` | 捕获屏幕特定区域位图 | 高敏感 |
| `clipboard` | 读取或写入系统剪贴板纯文本 | 高敏感 |
| `candidate-text` | 获取候选词文字与左邻上下文 | 高敏感 |
| `selected-text` | 读取当前窗口里用户选中的文字 | 高敏感 |
| `ocr` | 调用离线 OCR 识别引擎提取文本 | 普通 |

联网经独立 broker 进程 `lueying-broker.exe`：只能访问扩展清单 `network.allow` 声明、并经用户同意的域名。上下文按级授权：读选中文字要 `selected-text`，扩展没申请就调用失败。

## 分发与信任分级

扩展以 `.luext` 单文件分发：容器头 `LUEXT` + 1 字节版本，随后逐个存「u16 名字长 + 名字 + u64 内容长 + 内容」（小端）；名字必须是裸文件名，且不得是 `consent.json`（同意记录只由宿主写）。安装渠道按信任强度分级：

| 渠道 | 入口 | 校验 |
|---|---|---|
| 官方目录 | 设置 → 扩展 → 官方扩展，一键安装 | 每个文件按编译期内嵌目录的 SHA-256 校验 |
| 本地 .luext | 设置 → 扩展 → 运行期扩展 → 导入 | 容器结构与清单 API 校验，导入后走统一同意流程 |
| 开发者目录 | 把包目录直接放进 `%APPDATA%\lueying\extensions\` | 免打包，内容哈希与同意指纹照常核对 |
| 第三方目录源 | 远端目录 JSON（格式同官方目录） | 规划中，随发版基建落地 |

覆盖导入同 id 的包后，内容哈希变化令扩展自动挂起，等用户在设置里重新同意。

## 原生扩展（kind = "native"）

原生扩展是独立进程的服务提供者（如 PP-OCRv6 识别引擎），不进 Wasm 运行时：

- 清单声明 `kind: "native"` 与 `exe` 文件名；同意指纹把可执行文件字节一并纳入，文件一变即失效挂起。
- 进程由宿主的常驻宿主管：首次调用拉起，空闲 60 秒自动退出，模型常驻；运行于 AppContainer 沙箱（能力列表为空，无网络），并受 Job Object 内存与进程树限额。
- 沙箱恒开；原生扩展永不进入输入法进程，识别结果只能经宿主上屏。
- 同意对话框明示「包含原生可执行文件」；从官方目录与本地 .luext 导入的安装路径一致。

## 授权与审计机制

- **哈希指纹校验**：扩展在设置页首次启用时，系统根据清单及 Wasm 模块生成 SHA-256 内容指纹并记录于 `%APPDATA%\lueying\extensions\consent.json`。脚本内容变动后新版本自动挂起，直到用户在设置中再次确认。
- **审计日志追踪**：所有敏感原语调用实时写入 `%LOCALAPPDATA%\lueying\logs\ext-audit.log`，记录调用时间、扩展 ID、调用的服务方法与授权结果，日志绝不保存用户正文内容。

## 沙箱资源约束与熔断

| 资源项 | 限额标准 | 超限处理机制 |
|---|---|---|
| 线性内存 | 16 MiB | 内存增长即 trap，计入一次 OOM |
| Wasm 值栈 | 256 KiB | 栈溢出 trap |
| 初始化燃料 | 50 M | trap，扩展置为加载失败 |
| 命令燃料 | 200 M | trap，任务计入一次超时 |
| 外观燃料 | 20 M | trap，任务计入一次超时 |
| 命令空闲卸载 | 30 秒 | 无活动事件时整体丢弃 worker 与实例回收内存(外观包常驻) |
| 容错熔断门限 | 连续 3 次失败 | 自动将该扩展标记为 `disabled`，防止持续扰动 |
